# LEARNING APP FAMILY — SHARED ISLAND WORLD TOPOLOGY — 2026-09-22

Status: CROSS-APP SHARED WORLD AUTHORITY
Scope: Ready & Set / Hide & Seek / Snap & Pop shared world and navigation topology
Authority: latest TAKY + explicit user decision 2026-09-22

## 1. Fixed island invariant
The island environment is FIXED.
- Do not generate a different world per app.
- Do not randomize island geography between sessions.
- Do not reinterpret each app as a separate disconnected game world.
- App surfaces are regions and functions within one persistent island.

## 2. Entry / naming sequence
High-level world sequence:
CHARACTER / EXPLORATION CREW SETUP
→ DROP / VOYAGE ARRIVAL
→ ENTER FIXED ISLAND
→ NAME THE ISLAND
→ READY & SET BASE CAMP / MAP
→ NAME THE BASE CAMP
→ MOVE TO APP REGION

Island naming rules:
- island name is learner/family-facing world identity;
- name persists across sessions and app regions;
- renaming may be allowed later but must not reset progress/history;
- island name does not change geography or app ownership.

Base-camp naming rules:
- base-camp name is the learner-facing name of the Ready & Set hub;
- base-camp name persists across sessions;
- renaming must not reset Planner, Timer, goals, records, badges, or crew relationships;
- base-camp name is presentation identity, not a new data owner.

Drop / voyage is the island-entry transition language.
It is not required on every app switch; use for first entry or meaningful transition moments.

## 3. Ready & Set role
Ready & Set is the island BASE CAMP and MAP/HUB.
Ready & Set owns learning goals, Planner/date/time allocation, session/timer/base-camp state, cross-app completion reception, and broader family/parent sharing.
The Ready surface should visually communicate the fixed island map and routes into app regions.

## 4. Hide & Seek region
Hide & Seek occupies the JUNGLE / WATERFALL region of the fixed island.
Hide home is a regional base point, not the whole-island map.
Hide owns clue/homework intake, confirmed learning set, TRACE/LINK/PIECE, CATCH, cumulative memory/review.

## 5. Snap & Pop region
Snap & Pop occupies the BEACH region of the fixed island.
Snap remains owner of Exploration Crew identity/personality/behavior/intervention grammar.

## 6. Exploration Crew continuity
Character and companion setup happens at family/world level before or during island onboarding.
- current companion persists across app regions;
- character identity is carried by character_id / Explorer_ID;
- app switch does not reset companion relationship/history;
- crew function advantage by character remains forbidden.

## 7. Cross-app navigation
App switching should feel like movement across one island, not launching unrelated apps.
- Ready & Set = base camp / island map
- Hide & Seek = jungle + waterfall
- Snap & Pop = beach
Any future app region must be added to the SAME island map unless explicitly redesigned.

## 8. Visual continuity
- fixed island geography;
- consistent landmarks/routes;
- local atmosphere may vary while remaining part of the same island;
- UI overlays remain legible over illustration;
- random forest/ocean/cave backgrounds that break spatial continuity are forbidden.

## 9. Product boundary
Ready = goal/planner/base-camp authority.
Hide = retrieval/memory specialist.
Snap = expression/exploration-crew specialist.
World navigation and naming do not transfer authority.

## 10. No-silent-loss lock
Explicitly locked:
- fixed island environment;
- character / exploration crew setup before island journey;
- drop / voyage entry;
- island naming on first island entry;
- Ready & Set as base camp and island map;
- base-camp naming after base-camp entry;
- Hide & Seek at jungle / waterfall;
- Snap & Pop at beach;
- app-to-app movement occurs within the same island;
- island/base-camp renaming never resets learning history or ownership;
- Hide home is regional base point, not island-level hub.
