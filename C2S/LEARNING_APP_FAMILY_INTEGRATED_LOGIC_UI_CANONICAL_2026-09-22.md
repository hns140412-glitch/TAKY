## 4. Explorer / Character identity model

### 4.1 Persistent identity

`Explorer_ID` is persistent.

Character visual representation is versioned:
`Explorer_ID → Character Visual ID v1 → v2 → v3 ...`

A profile/photo update does NOT create a new Explorer.

### 4.2 Source authority

For a Character Visual ID version:
- current approved source photo = highest visual identity authority
- profile age/birth information + elapsed time = age/proportion authority
- image must NOT be used to infer age as the authoritative progression source

### 4.3 Likeness-first stylization

User character must preserve recognizable visible traits:
- face shape
- eye shape/spacing/expression cues
- mouth and relative feature placement
- hairstyle/hairline cues
- age impression
- natural body proportions.

FORBIDDEN:
- generic “cute child” averaging
- identity substitution
- excessive SD/chibi/dwarf proportion
- large-head/short-body compression that hides age differences
- adult-like proportion for a child
- franchise imitation.

Rule:
STYLE TRANSFER ALLOWED.
IDENTITY COMPRESSION FORBIDDEN.

### 4.4 Age-aware progression — FAMILY_LOCKED PRINCIPLE

The character should visibly change with age/time while remaining the same child.

May change:
- body proportion
- limb length
- height impression
- face baby-fat / maturity balance
- clothing fit
- posture
- hairstyle when profile evidence changes
- age-appropriate rendering details.

Must persist:
- Explorer_ID
- core identity cues
- Character lineage
- Crew relationship
- Badge history
- Island/Base Camp history
- Episodes and records.

Exact age-stage thresholds = OPEN.
Age progression must use explicit profile age context, not visual guessing.

### 4.5 Profile update contract — NEW REQUIRED CONTRACT

PROFILE PHOTO UPDATED
→ register new source reference
→ preserve current Explorer_ID and Character lineage
→ evaluate whether Character refresh is requested/needed
→ generate/update same-identity candidate(s)
→ age-aware proportion context
→ consistency review
→ human confirmation
→ activate next Character Visual ID version
→ preserve prior versions for history.

Hard rule:
PROFILE_CHANGE != SILENT_CHARACTER_REPLACEMENT.

The current one-shot Character Core is therefore incomplete for long-term profile lifecycle until this contract is implemented.

### 4.6 Character projection

Current consumer contract:
`CHARACTER_VISUAL_ID_PROJECTION_V02`

V02 supersedes V01 before Ready / Hide / Snap integration.
