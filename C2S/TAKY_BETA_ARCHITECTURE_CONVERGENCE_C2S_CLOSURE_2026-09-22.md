## 3. Root-cause model after correction

### Strong
1. OWNER TYPE COLLAPSE
   - semantic owner, mutation/write authority, runtime/state owner, implementation module owner and UI host are often all called “owner”.
2. CANONICAL GENERATION DRIFT
   - legacy GUIDE / MAIN / Ready-centered structure coexists with newer Learning Identity / Learning Engine / Planner / Family structure.
3. SHADOW CURRENT STATE / PROJECTION
   - STATE, persistent active profiles and volatile registries may copy current truth.
4. OPERATIONAL EXPRESSION PROLIFERATION
   - sound principles are expressed through multiple protocols, profiles, gates, validators and projections.
5. GOVERNANCE ACTIVATION GAP
   - rules are generally good but the cost of selecting/applying the correct subset can be high.

### Corrected / weakened
6. INCIDENT -> GLOBAL RULE LEAK
   - direct evidence is weaker than initially hypothesized. Ready/Hide/Snap incidents are often contained locally.
   - the stronger pattern is PARALLEL SELF-MANAGEMENT ACCUMULATION: every layer adds its own state, validators, migration guards and compatibility mechanisms.

### Rejected as primary root cause
7. C2S itself
   - C2S remains necessary for lossless lineage/correction/owner transfer. Risk exists only if it absorbs current execution truth or becomes a shadow canonical.
