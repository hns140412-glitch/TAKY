## 0. MASTER DECLARATION — HARD LOCK

Primary purpose:
The child repeatedly learns to understand assigned work, set goals, allocate work within real life time, start at an appropriate time, finish, reflect and improve the next plan, so that self-directed learning management and time awareness grow over time.

Secondary purpose:
Observe actual learning experience — time, amount, difficulty, success, mistakes, stuck points, explanations, help/check events and performance evidence — according to subject characteristics, so the child and parent can make the next learning cycle better.

PRIORITY SHALL NOT BE REVERSED.

`계획 → 실천 → 경험 → 관찰 → 개선 → 더 나은 다음 계획`

Learning analysis is not a higher-order justification for increasing study volume.
Guide success = the child needs Guide less over time.

## 1. OWNERSHIP / AUTHORITY — HARD LOCK

`MAIN = HOW TO MANAGE`
`SUB-MASTER = HOW TO UNDERSTAND`
`FUNCTIONAL APP = HOW TO HELP EXECUTE`

- life schedule / available-time interpretation at management level
- weekly/daily allocation
- priority and deadline coordination
- workload placement using subject interpretation
- Carry-over and rescheduling
- plan-vs-actual adjustment
- next-plan forecast

- difficulty and cognitive-load interpretation
- concept / skill target

- method recommendation
- subject-specific performance/observation interpretation
- uncertainty / confidence

FUNCTIONAL APP owns:

Hard boundaries:

- MAIN SHALL NOT invent subject difficulty without subject/evidence support.
- Functional App SHALL NOT absorb MAIN schedule/family/common authority.
- Guide SHALL NOT replace or evaluate the professional teacher role.
- External AI / Tool / Skill SHALL NOT override MASTER authority.
- `SUBJECT INTERPRETS; MAIN ALLOCATES.`

## 2. SCHEDULE FIRST, ASSIGNMENT SECOND — TOP OPERATING PRIORITY

`SCHEDULE FIRST, ASSIGNMENT SECOND`

The planning engine begins from the child's real life schedule and available windows, not from a pile of homework.

Canonical management flow:
`CHILD LIFE SCHEDULE → WEEKLY AVAILABLE WINDOWS → ASSIGNMENT INTAKE → SUBJECT INTERPRETATION → LEARNING UNIT SIZING → WORKLOAD / DIFFICULTY → CAPACITY / DEADLINE → WEEKLY PLAN → DAILY ADAPTIVE TODO → CHILD CHOICE → EXECUTION → REAL-TIME ADJUSTMENT → RESULT / CHECK / HELP → SUBJECT OBSERVATION → MAIN SUMMARY → PARENT SUPPORT → CALENDAR / HISTORY → FORECAST → NEXT PLAN`

Closed-loop realization flow:
`CHILD LIFE SCHEDULE → ASSIGNMENT INTAKE → MAIN PLAN → PLAN CONFIRM → EXECUTION → SUB-MASTER / APP → ARTIFACT → REVIEW / FINALIZE → LOCAL SAVE → SHARE / SUBMISSION → CALENDAR → HISTORY → MAIN OBSERVATION → NEXT PLAN`

Local result save precedes reliance on external share/calendar acknowledgement. External failure SHALL NOT delete or invalidate the child's locally committed learning result.

## 3. SCHEDULE / CAPACITY CONTRACT — HARD LOCK

Default time unit may use `25분 학습 + 5분 휴식`, but this is a planning aid, not a mechanical mandate.

Morning:
- treat before-school time as a compressed session;
- initial 1-block level may expand to two short focus blocks as adaptation grows;
- prefer an overall approximately 40-minute morning target over mechanically forcing 55 minutes.

After academy / main study:
- short available windows may be used when appropriate;
- 3–4 blocks after dinner may represent capacity, not mandatory volume.

Hard locks:
`FREE TIME EXISTS ≠ MUST STUDY`
`CAPACITY ≠ REQUIRED STUDY AMOUNT`
`PLANNED STUDY END ≤ 22:00`
`22:00 PLANNED END ≠ FORCED ACTUAL SHUTDOWN`
`OVERTIME ≠ FOCUS FAILURE`
`OVERTIME ≠ STUCK`

If actual execution passes the planned boundary, distinguish possible reasons such as start delay, focus variation, difficulty, estimate error, break overrun, productive deep thinking or actual stuck state instead of automatically assigning failure.

Plan contract candidate retained for continued validation:
`PLAN IS NEGOTIABLE; DEADLINES / EXTERNAL COMMITMENTS ARE CONSTRAINTS; NOT EVERY PLANNED TASK IS MANDATORY TODAY.`

This remains CANDIDATE until explicitly finalized, but current behavior SHALL NOT contradict the confirmed hard locks above.

## 4. WORKLOAD / ALLOCATION CONTRACT

MAIN allocates learning load, not empty time.

Primary allocation inputs:
`available time + deadline + expected duration + difficulty / cognitive load + divisibility + recent actual performance + time-of-day characteristics`

Difficulty / load interpretation may include:
- volume / repetition
- new concept
- reasoning
- reading
- writing
- calculation
- familiarity
- likely parent/teacher involvement

Fixed rules such as “hard work always goes in the morning” are prohibited unless supported by actual child pattern/evidence.

## 5. LEARNING UNIT SIZING

Physical assignment amount ≠ executable learning unit.

`ASSIGNMENT → SUBJECT INTERPRETATION → CONCEPT / SKILL TARGET → DIVISIBLE LEARNING UNITS → DIFFICULTY / COGNITIVE LOAD → ESTIMATED EFFORT RANGE`

Use the subject-appropriate unit: page, problem, section, chapter, passage, word set, performance segment, piano section, etc.

Subject interprets units; MAIN combines those units with schedule, capacity and deadline.

## 6. TASK STATE / CARRY-OVER / TIME AWARENESS

Canonical task states:
`PLANNED → READY → IN_PROGRESS → COMPLETED`
or
`DEFERRED → CARRY_OVER → RESCHEDULED`

Incomplete work is not deleted or punished.
`미완료 = 다음 계획에서 내가 해결해야 할 Carry-over`

Useful plan-vs-actual evidence includes:
- plannedStartAt
- actualStartAt
- startDelay
- plannedDuration
- actualDuration

Repeated plan-vs-actual differences improve future estimates and allocation; they do not automatically become diagnosis or blame.

## 7. CHILD OWNERSHIP — HARD LOCK

`Guide 주도 보조 → 선택권 이전 → 아이 계획 → 아이 조정 → 아이 주도 / Guide 대기`

A single failure or late day SHALL NOT cause Guide to reclaim full control.
MAIN recommendations are recommendations, not commands.
Ready & Set must allow the child to agree, adjust and execute the current goal within the applicable plan/constraint boundaries.

## 8. GUIDE CORE / INTERVENTION — HARD LOCK

Guide is not the child's answer proxy, grader, surveillance system or permanent controller.

Base behavior:
`관찰 → 필요한 순간만 개입 → 생각할 여지 → 쉬운 도움 → 아이에게 다시 주도권 반환`

- Silence by Default while the child is working well.
- compare with the child's past self, not others.
- avoid blame and inflated praise.
- use age-adaptive easy language first.
- easy words → terminology only when useful.
- short, clear, actionable first; depth when wanted/needed.

Hard locks:
`OBSERVATION ≠ DIAGNOSIS`
`LONG TIME ≠ STUCK`
`CHILD SELF-REPORT ≠ VERIFIED LEARNING OBSERVATION`
`OVERTIME ≠ FOCUS FAILURE`
`CHECK_REQUEST ≠ HELP_REQUEST`
`QUESTION SUBJECT ≠ CURRENT TASK SUBJECT`

## 9. WHY / CURIOSITY / LEARNING MODE

Self-direction includes discovering WHY, exploring, connecting prior knowledge and explaining in the child's own words.

`Guide WHY → child notices WHY → child creates WHY → explores / connects / judges independently`

WHY is not a technique for refusing direct answers.
Question count SHALL NOT become a score/reward competition.
Question/help ≠ weakness.

Focused Practice:
`FOCUS > EXPLORE`
- short question: quick answer then return;
- deeper question: save to Curiosity Record and return, then explore later.

Deep Thinking:
`WHY → explore → connect → understand → explain in own words → possible new WHY → return`

Final learning mode uses:
`MAIN operating context + SUBJECT interpretation + current child state → FINAL SESSION MODE`

## 10. ANSWER FIRST / QUESTION INTENT — HARD LOCK

1. CURIOSITY / KNOWLEDGE QUESTION
→ direct easy answer → easy reason → optional example/connection.

2. HOMEWORK FINAL ANSWER REQUEST
→ concept/method/hint → do not write the final homework answer on the child's behalf.

3. RETRIEVAL / PRACTICE QUIZ
→ child recalls/answers first → then feedback/explanation.

`ANSWER FIRST ≠ ALWAYS SHOW ANSWER`
`OFF-TOPIC ≠ DISTRACTION`

## 11. LEARNING METHOD ROUTER

Reusable method candidates:
`UNDERSTAND / RETRIEVE / APPLY / COMPARE / EXPLAIN / VISUALIZE / PRACTICE / CREATE / PERFORM / REFLECT`

Method ≠ subject. The same method is interpreted differently by each subject.
Do not force one method across all subjects.
Retrieval does not replace new-concept understanding.
Speed recall does not dominate thinking/creative tasks.
Piano/practice requires actual performance evidence where applicable.

## 12. ASSIGNMENT INTAKE / OCR / ANSWER KEY

Parent homework intake should support fast continuous capture rather than repeated classification during shooting.

`continuous capture → temporary thumbnails → add / delete / retake → finish capture → batch analysis → grouping → Review-before-Commit → CONFIRMED ASSIGNMENT`

Grouping evidence may include cover, subject/unit/title, problem content, page number, capture order, layout similarity and answer-key pattern. Capture order is evidence, not an absolute rule.

`CAMERA ORIGINAL ≠ OCR DRAFT ≠ CONFIRMED ASSIGNMENT`

Answer-key source is separate from assignment source.
`ANSWER KEY EXISTS ≠ CHILD CAN ACCESS ANSWER`

Answer key may be registered before or after the child requests checking.
`ANSWER_KEY_REQUIRED` is not child failure.
AI grading is candidate assistance; uncertain handwriting/interpretation requires human review. AI forced correction/relearning remains HOLD.

## 13. HELP / CHECK / FAMILY / TEACHER BOUNDARY

CHECK:
`SOLVING → SOLVED → CHECK_REQUESTED → CHECKED`
CHECK = child has finished and asks for parent confirmation/grading.

HELP:
`SOLVING → STUCK_POSSIBLE → STUCK_SPECIFIC / UNCLEAR → UNKNOWN_STUCK → HELP_REQUESTED → HELP_RECEIVED / RETURN`
HELP = human help needed during learning.

`CHECK_REQUEST ≠ HELP_REQUEST`
CHECK-specific audio SHALL NOT be reused as HELP semantics.

Stuck detection:
`STUCK DETECTION ≠ STUCK JUDGMENT`
`오래 걸림 ≠ 막힘`
Ask a short confirmation first; if the child says they are thinking, retreat. Do not infer the cause and launch a long explanation without evidence.

Guide / Parent / Teacher:
- Guide: observe, connect, explain briefly, hint, identify patterns, route help.
- Parent: judge real-world need, correct AI interpretation, respond to HELP/CHECK, support schedule.
- Teacher: professional teaching, misconception correction, additional-practice range, repertoire/professional-performance judgment.

Parent Mode is not surveillance.
Parent support states may include:
`PROGRESSING / CHECK_NEEDED / HELP_NEEDED / SCHEDULE_ADJUSTMENT / ENCOURAGEMENT_MOMENT`
Use event-driven support, not constant monitoring.

Family routing:
`current subject → HELP/CHECK → default helper → current day/time → family availability → child's explicit choice → Guide TTS → connection`
`LIVE FAMILY STATE > DEFAULT FAMILY SCHEDULE`

## 14. VOICE / AUDIO / PRACTICE EVIDENCE

Conversation voice session:
`ENTER → MIC PERMISSION → AUDIO HANDOFF → GUIDE SPEAKING → LISTENING → CHILD SPEAKING → END-OF-SPEECH → STT / intent → SUB-MASTER → GUIDE RESPONSE → ... → EXIT → MIC OFF → restore original timer/BGM/task`

Hard behaviors:
- Timer keeps running unless the child explicitly pauses under the app contract.
- BGM pauses/ducks when it would compete with voice/recording.
- Mic is active only during an active session.
- Raw audio permanent save OFF by default.
- `듣는 중 ≠ 녹음 저장 중`.
- TTS provider is replaceable.

Voice Practice Engine may support:
`Read Aloud / Listen Back / Guide Model Reading / Expression Compare / Retry / Final Take / Audio File / Share-Submit`

Recording infrastructure is shared-capability; subject interpretation is domain-owned.

Practice Evidence candidate flow:
`BEFORE → PRACTICE → AFTER → COMPARE → PRAISE → ONE NEXT IMPROVEMENT`

Hard separation:
`RECORDING ≠ FINALIZED ≠ SHARED ≠ SUBMITTED`
`STOPPED ≠ FINALIZED`
`FINALIZED ≠ SHARED`
`SAVED ≠ SHARED`
`SHARE BUTTON ≠ SHARED`
`SHARED ≠ SUBMITTED`

Identity separation:
- authentication ≠ member identity ≠ role ≠ storage connection.
- memberId is the internal stable identity; visible names/kinship labels are presentation/context.
- do not require a separate Google account for each child.

Storage:
`LOCAL-FIRST + DRIVE-BACKED HYBRID`
- Device Local DB = execution state/cache/durable local state as required by project contract.
- Google Drive = long-term/family storage and synchronization surface.
- Sync Engine = version/conflict/reconciliation.

Important sync events may include assignment, plan confirm, completion, CHECK, HELP, answer key and important settings. Checkpoint/night sync may handle ordinary data, but sync SHALL NOT interrupt active late learning merely because a clock threshold is reached.

Multi-volume storage may rotate when capacity requires:
`OLD STORAGE = READABLE`
`NEW STORAGE = WRITABLE`
Forced migration of all historical files is not required unless a later approved policy requires it.

Family privacy:
`FAMILY BOUNDARY = DATA BOUNDARY = STORAGE BOUNDARY`
`SHARED ENGINE ≠ SHARED DATA`
GitHub is not the private child-learning-data store.
