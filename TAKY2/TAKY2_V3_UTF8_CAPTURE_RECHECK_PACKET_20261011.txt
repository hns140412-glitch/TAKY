CONTEXT
The prior final micro recheck (receipt pf:taky2-v3-final-micro-codex-20261011:3dad5028561f0e7d) returned PASS.
During that run, Python's subprocess reader thread raised UnicodeDecodeError (Windows cp949 locale) on the Codex CLI's UTF-8 stderr.
With text=True and no encoding, a decode failure leaves completed.stdout/stderr as None, which subprocess_runner then maps to "".
Consequence: an external review verdict could be silently lost while returncode=0 is persisted as RETURNED (evidence loss).
The Codex path survived only because it reads a bridge-owned last-message file; the Claude PACKET_ONLY path has no such fallback.

FIX (only change): run_kwargs gains encoding="utf-8", errors="replace".
This also makes stdin `input=` text encode as UTF-8 instead of the locale codec; the tempfile stdin path already used UTF-8.

REGRESSION TEST:
def test_subprocess_runner_decodes_utf8_output_independent_of_locale():
    import sys
    from TAKY2.bridges import subprocess_runner

    # Model CLIs emit UTF-8 (e.g. em dash); a locale codec such as cp949 must
    # not silently drop stdout/stderr evidence.
    result = subprocess_runner({
        "argv": [
            sys.executable,
            "-c",
            (
                "import sys; "
                "sys.stdout.buffer.write('VERDICT: PASS \\u2014 ok\\n'.encode('utf-8')); "
                "sys.stderr.buffer.write('banner \\u2014 \\u2713\\n'.encode('utf-8'))"
            ),
        ],
        "timeout_sec": 5,
    })
    assert result["returncode"] == 0
    assert result["stdout"] == "VERDICT: PASS — ok\n"
    assert result["stderr"] == "banner — ✓\n"
