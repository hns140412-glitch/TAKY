## 7. Artifact / UI / design learnings

These affect Worker Role profiles and lower-owner design/artifact pipelines.

### STAGED ARTIFACT WORKFLOW
For large artifacts:
plan/design -> sample -> inspect -> full build -> final verification.
One-shot output is not automatically preferred.

### HUMAN EDITABLE OUTPUT
When the deliverable requires visual/structural fidelity, preserve an editable human correction surface where possible.

### TRANSFORM EXISTING ASSET BEFORE RECREATE
When an approved source exists:
reuse/transform first;
do not recreate from scratch unless the requested change requires it.

### LOCAL EDIT BEFORE REGENERATION
For small corrections:
prefer bounded local edit when it preserves source identity and reduces change surface.
Representative PPT test found local edit materially faster with fewer package changes.
Do not universalize the exact speedup.

### DESIGN TASTE AS EXPLICIT CONSTRAINT
“Make it pretty” is not a sufficient design contract.
Use:
references / taste constraints / forbidden clichés / visual rules / rendered review.

### SOURCE ASSET QUALITY SETS OUTPUT CEILING
Weak or incorrect originals cannot reliably be fixed by more orchestration alone.
Preserve high-quality source assets and provenance.
