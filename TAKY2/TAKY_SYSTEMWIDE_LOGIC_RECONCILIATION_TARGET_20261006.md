# 4. Recommended Shepherding Control Plane

## 4.1 USER ??Key Owner / Final Authority

USER owns:
- purpose,
- desired outcome,
- non-negotiables,
- explicit corrections,
- protected exclusions,
- approval of authority-changing / high-impact / irreversible actions.

USER does not own:
- routine debugging,
- AI coordination,
- recoverable file/source search,
- repeated test diagnosis,
- ordinary route recovery.

## 4.2 TAKY ??System / Governance / Orchestration Framework

TAKY owns the contracts that preserve:
- Key,
- authority,
- context,
- state,
- evidence,
- ownership boundaries,
- role relationships,
- execution truth.

TAKY is not a model, worker, dog, or UI.

## 4.3 ChatGPT ??Lead Orchestrator

Lead responsibilities:
- interpret and clarify intent without rewriting it.
- compile applicable MASTER/domain/app rules.
- choose control roles.
- choose work roles.
- construct execution contracts.
- choose agent/tool based on fit and necessity.
- maintain whole-system view.
- integrate results.
- detect conflicts/omissions/drift.
- report only USER decisions that truly require USER authority.

Lead may:
- route,
- assign,
- pause,
- resume,
- retry using a materially different route,
- re-plan,
- package escalation.

Lead must not:
- silently change Key.
- silently discard CLOSED/protected requirements.
- promote evidence without validation.
- turn a tool/model into permanent semantic owner.
- call expensive agents because a role name exists.

## 4.4 NAVIGATOR ??Direction / Trajectory Control

Question:
**"Are we still moving toward the USER-intended result?"**

Owns:
- intent drift detection.
- scope drift.
- priority/order correction.
- overengineering detection.
- wrong destination/path detection.
- return-to-Key routing.

Primary signal:
`Trajectory Deviation`.

Navigator does not own semantic meaning of lower apps; it compares execution against the semantic owner.

## 4.5 GUARDIAN ??Integrity / Boundary / Recovery Control

Question:
**"What is being lost, corrupted, overclaimed, crossed, or silently changed?"**

Owns detection/classification of:
- omission.
- data/evidence loss.
- ownership leakage.
- authority leakage.
- regression.
- false PASS/DONE.
- stale candidate promotion.
- privacy/security boundary violations.
- inconsistent state transition.

Outlier classification must be:
`ERROR / NOVEL_EVIDENCE / INTENTIONAL_EXCEPTION / UNKNOWN`

Do not automatically treat every outlier as an error.

Guardian behavior:
`DETECT ??CLASSIFY ??CONTAIN/RECOVER ??VERIFY ??RESUME`

## 4.6 DRIVER ??Momentum + SAVEY Economy Controller

Question:
**"What is the cheapest sufficient way to make the next verified progress without stalling?"**

Driver is not "push harder".
Driver is:
`MOMENTUM + SAVEY`

Driver states:
`PUSH / HOLD / THROTTLE / RESUME`

Driver responsibilities:
- keep productive work moving.
- avoid validation replacing work.
- minimize repeated agent/tool calls.
- batch related work.
- reuse existing evidence/context.
- prefer deterministic/local methods where sufficient.
- prefer already-paid/subscription capability before metered API.
- choose lowest sufficient capability, not lowest-quality capability.
- throttle unnecessary parallelism.
- stop external side effects that add no new evidence.

Recommended KPI:
`VERIFIED_PROGRESS / TOTAL_RESOURCE_COST`

Resource cost includes:
- money,
- model quota,
- tokens,
- remote calls,
- CPU/time,
- human attention,
- duplicate work,
- rework.

### SAVEY economy sequence

`NECESSITY ??REUSE ??LOCAL/DETERMINISTIC ??EXISTING SUBSCRIPTION/SESSION ??BATCH ??LOWEST SUFFICIENT CAPABILITY ??METERED/PAID ONLY WHEN JUSTIFIED/AUTHORIZED`

**CHEAPEST != CHEAPEST_SUFFICIENT**

Acceptance criteria may never be lowered to reduce cost.

## 4.7 SCOUT ??Unknown / Evidence / Alternative Discovery

Question:
**"What material fact, evidence, alternative, or risk do we still not know?"**

Scout is activated only when uncertainty materially affects the result.

Owns:
- source recovery.
- external research.
- GitHub/community/official evidence discovery.
- unknown precondition discovery.
- alternative solution discovery.
- candidate opportunity discovery.

Scout flow:
`DISCOVER ??EVIDENCE ??COMPARE ??LOCALIZE ??VERIFY ??ADOPT/ADJUST/HOLD/REJECT`

Scout findings never become authority automatically.

Keep the external name `COST` for backward compatibility.
Internally it is an economy gate, not merely a price gate.
