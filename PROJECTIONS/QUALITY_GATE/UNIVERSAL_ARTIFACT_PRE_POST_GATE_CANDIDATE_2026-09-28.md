## Producer lifecycle
`HUMAN INTENT -> THINK AGAIN -> KEEP YOUR KEY -> FIND A WAY/SOLVE -> YOU'RE THE KEY -> VERIFY/CORRECT/CONTINUE`
The cycle governs the **entire work**, not a redefinition of slogans as gate names.

### Before creating deliverable bytes — compact PRE-GATE
1. Recover actual source/original, approved format/UI/asset and latest user correction; check current canonical/project authority and exact live ref when material. Treat unavailable evidence as unknown, not absent.
2. Freeze required output (including format, coverage and intended real use), protected source/state, changeable scope and hard stop conditions. Translate applicable rules into execution effects.
3. Set a small **artifact-specific acceptance contract** before producing it: semantic/content correctness; traceability to source; exact style/template/layout identity; functional/runtime/print/visual quality where applicable; preserved content; and how each criterion will be witnessed.
4. Select the smallest adequate verification route, including real render/preview for layout-dependent artifacts. Plan a materially independent check for high-risk items. Do not ask the user to run CMD/PowerShell or diagnose AI-side faults.
5. If an indispensable original or authorization is inaccessible, record a bounded blocker; pursue authorized alternate recovery rather than fabricate it. No self-certified PASS.

### Build / improve
Create the requested **result**, not another checklist/tool in lieu of the result. Preserve originals; compare early representative samples with reference; repair material differences as work proceeds. Progress/validation is subordinate to output quality. Do not silently merge/deploy/publish.

### After creation, before calling it complete — POST-GATE
- Open/parse the artifact, inspect actual content against source, verify scope/date/name/numeric/citation integrity, and detect omissions and duplicates.
- View/render final intended presentation (Excel print view; DOCX/PDF pages; PPT slides; image composition; UI screens and states). Compare against original approved visual/layout, including readability, clipping, grouping, whitespace, typography and page breaks.
- Exercise applicable interactions, formulas, tests, links and edge cases. Verify original/protected state and downstream regressions.
- Compare **integrated result** rather than passing isolated components; correct and rerun only the targeted checks changed by correction.
- Verify the actual delivery path and provide truthfully bounded evidence. A valid ZIP/file signature, static parse or self-report is not a visual, semantic, runtime or device PASS.
